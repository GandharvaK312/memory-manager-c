the garbage collector basically scans the heap and checks if the pointers in the heap
point to something in the heap, if yes, good, if not then they are deallocated

GC (heap_collect) — done:

mark_region scans a memory range one word (uintptr_t) at a time.
Each word is treated as a *candidate* pointer — if its value falls
inside any alloced_chunks entry, that chunk gets marked reachable,
and mark_region recurses INTO that chunk (so a tree node only reachable
through another heap object still gets found, not just direct stack
pointers).

starting point: stack, from current frame address (__builtin_frame_address(0))
up to stack_base (captured once in main() before anything else runs)

after marking: sweep — walk alloced_chunks, anything NOT marked
reachable gets heap_free()'d

this is "conservative" because it doesn't know which stack words are
real pointers vs plain integers that just happen to look like valid
heap addresses. it checks anyway and treats matches as pointers.
false positives (keeping garbage alive) possible, false negatives
(freeing live memory) should not be, assuming stack scanning is correct.

test in main.c: build small binary tree via heap_alloc, keep root
pointer alive -> heap_collect() should keep whole tree.
set root = NULL -> heap_collect() should free entire tree, since
nothing on the stack points into it anymore.
